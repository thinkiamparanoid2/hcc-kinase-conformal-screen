# HCC kinase conformal screen — status and next steps

As of 2026-10-20. Written for whoever picks this up next, human or agent.

## The one next step

Change the applicability-domain width budget from **1.65** to **1.25** pIC50 units in step 04,
re-run steps 04 and 05, and look at what the hit counts become. Nothing else should start before this.

Why: the domain filter is the project's headline mechanism and at 1.65 it switches itself off on two
of three targets. At 1.25 it binds on all three. This is one constant and a re-run, not new science.

## What is done

Steps 01 through 07 have all run on the re-fetched data, at the full docking protocol with no reduced
budgets. 36 unit tests pass. The pipeline is reproducible from `environment.yml` or the `Dockerfile`,
and every number in the generated report is read from `results/metrics/`, none typed by hand.

The inactive-class gap is closed: step 01 now requests all five `standard_relation` values, so the
docking enrichment control is a real active-against-inactive test rather than potent-against-weak.
Measured inactives: FGFR4 1,078, EGFR 1,659, VEGFR2 1,666.

## The honest assessment

**Publishable as a methods and negative-results paper. Not as a hit-discovery paper.**

A discovery framing does not survive review: there is no experimental validation, 3,220 of the 3,271
hits come from FGFR4, whose domain filter is inert and whose pocket fails redocking, and the conformal
coverage guarantee does not transfer to natural products.

The contribution that does hold up is the reporting rigour and what it caught. The controls were built
to be able to fail, and two of three failed. Most screening work either skips these checks or quotes
the flattering variant of them.

**VEGFR2 is the one target where every link survives its own control**, and it is the natural positive
example for a methods paper: the domain threshold binds and admits 0.30% of the library, enrichment is
0.693 with the confidence interval excluding 0.5 and clearing its permutation null, and redocking
passes at 0.577 A. It gives 111 interval-active hits, 7 on scaffolds absent from training.

## The key finding, verified

The applicability domain's existence depends on a tolerance parameter that published work almost never
states. From `results/metrics/final_model_*.json`, field `tau_by_budget`:

| width budget (pIC50) | FGFR4 | EGFR | VEGFR2 |
|---|---|---|---|
| 1.00 | — | 0.7 binding | — |
| 1.25 | 0.7 binding | 0.7 binding | 0.7 binding |
| 1.50 | non-binding | 0.6 binding | 0.5 binding |
| **1.65 (used)** | **non-binding** | **non-binding** | **0.5 binding** |
| 2.00 | non-binding | non-binding | non-binding |

The ordering is not even consistent across targets, which sharpens the point. Supporting context: the
median Tanimoto similarity between the screened library and the training sets is 0.182 (FGFR4), 0.217
(EGFR) and 0.206 (VEGFR2), so a filter admitting 100% of the library at that distance is demonstrably
vacuous. Make this sweep a headline figure, not a line in a log.

## What to do after the re-run

In order of payoff.

1. **Measure interval coverage on real natural-product bioactivity.** This is the control the paper is
   missing. ChEMBL supplies only 9 to 28 natural-product-like calibration molecules per target against
   the 60 needed, so no natural-product stratum can be fitted and every library interval is an
   extrapolation. NPASS, and the natural-product subsets of ChEMBL and BindingDB, hold
   natural-product-kinase activity pairs; a few hundred would turn the biggest caveat into a measured
   result.
2. **Run the pipeline over 10 to 15 kinases instead of 3.** Mostly compute. "Domain filters are often
   vacuous" is an anecdote at n=3 and a finding at n=15. It also answers the obvious reviewer counter,
   that a bad width budget was simply chosen.
3. **Add a second and third domain method** — distance-to-model, bootstrap variance, inductive against
   Mondrian conformal — and report whether they agree on which compounds are out of domain.
4. **Add property-matched decoys** alongside the ChEMBL inactives in the docking control. Two
   independent negative classes is much harder to dismiss.
5. **Do the temporal split prominently**, training pre-2015 and testing post-2020. `first_year` is
   already stored. Low prospective accuracy is a field-wide problem and reporting it honestly counts.
6. **Rescore the existing docking poses.** The redocking failures are ranking failures, not sampling
   ones: the near-native pose exists on disk at rank 4 for EGFR and rank 7 for FGFR4, within
   0.82 kcal/mol of the top-scored pose. If a rescoring function recovers it to rank 1, that is a
   clean small result. If not, report docking as unusable for these pockets and stop.
7. **Get 5 to 12 VEGFR2 hits into a kinase assay.** The only route to a discovery paper. A commercial
   panel on purchasable compounds is a few hundred dollars, or a collaboration with any lab running
   kinase assays. One confirmed hit changes the paper's category.

**Do not** add a graph neural network or a pretrained chemistry transformer, screen a larger library,
or add targets to the screen alone. None of these touch the real weakness, which is that the
uncertainty estimates have no demonstrated validity on natural products.

Realistic venues for the methods framing: Journal of Cheminformatics, Molecular Informatics, RSC
Digital Discovery. JCIM becomes plausible with the multi-target generalisation.

## Hazards worth knowing before you touch anything

- **A Remote Control session on the Windows machine parks after roughly an hour of thread silence**,
  whatever is running. A detached job keeps going and only the log stops being written, so read
  progress from process CPU time and pose files rather than the log. Only a message from the user in
  the thread restarts the session; a coordinator relay does not, and a cloud session cannot message it.
  Plan long runs in chunks that push after each step.
- **Step 06 cannot be resumed naively.** Poses are skipped when they already exist, but the Open Babel
  receptor conversion runs unconditionally and its hydrogen placement is not deterministic, so a
  resume docks earlier poses against one receptor build and later ones against another. Delete the pose
  directory before resuming a paused step 06.
- **Three bugs were found and fixed in this run**, each with a test; do not reintroduce them. Step 03's
  checkpoint keyed on `(target, seed)` only and silently reused rows computed from older data, which
  would have selected the model family from a mixture of two datasets. Step 06's candidate staleness
  guard required column names that never existed in the file it reads, so candidate docking had never
  once run. Step 06 crashed instantly on Windows because it deleted a scratch file RDKit still held
  open.
- **A passing test that asserts a column name proves nothing** unless something also reads the real
  file's header. That is exactly how the candidate-docking bug survived.
- **RDKit's `GetBestRMS` superimposes before measuring and is not a pose-prediction metric.** Use
  `CalcRMS`. EGFR reads 1.78 A superimposed against 8.004 A in place; quoting the former would call a
  wrong-subpocket pose a success.
- **EF and BEDROC assume a large library with few actives.** On the balanced 100-compound control a
  random ranking gives BEDROC near 0.50, so every metric is reported against a label-shuffled null on
  the same design.
- **Vina scores are receptor-specific** and are never compared across pockets as evidence of
  selectivity; use the within-target z-scores.
